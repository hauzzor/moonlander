## Original request

Split from T-0009 so the game's pure modules, renderer, and static page hooks can
be rebuilt while the simulation leaves and integration are in progress.

## Goal

Provide the game's DOM helpers, input mapping, HUD formatting, seed helpers,
renderer, ship and backdrop drawing, layout, and static test hooks. The game loop
and wiring are integrated by T-0009.

## Current behavior

The old shell targets the previous game. T-0004 rebuilt the field renderer and
camera; this ticket rebuilds the remaining game-side pure modules and renderer.

## Desired behavior

- DOM and canvas helpers with safe initialization and DPR handling.
- Input mapping for Q, W, Space, E, and R; latches reset on blur and page hide.
- HUD formatting for hull, speed, progress, score, thruster states, autopilot
  status, and seed.
- Seed parsing, display, copy, input, load, and unsigned 32-bit handling.
- Canvas renderer orchestration for the field, ship, flame, backdrop, and
  optional sensor-render hook.
- Static `data-testid` hooks in `index.html`, state-driven by the wiring in
  T-0009.
- Instructions in `index.html` mention Q, W, Space, E, and R and describe staying
  inside the tunnel.
- Responsive layout and canvas DPR.
- Rendering reads simulation and field state only; it never mutates them.
- Consume T-0004's camera and field renderer read-only.

## Non-goals

- The fixed-step game loop, `main.ts`, `game.ts`, and seed-controls wiring.
- Sensor console behavior and radar drawing, owned by T-0016.
- Changing simulation behavior, sensor math, or tunnel geometry.
- New controls, touch input, audio, multiplayer, or leaderboards.

## Decision log

| Decision | Choice | Rationale |
| --- | --- | --- |
| Module split | Pure modules and renderer | Enables parallel sim work |
| Hooks | Static in index.html | Playwright contract |
| Camera | Consume T-0004 | No second writer |
| Sensor render | Optional hook | T-0016 adds without touching render/index.ts |

- The public simulation API from T-0003 is frozen.
- T-0004 owns `packages/game/src/camera.ts` and
  `packages/game/src/render/field.ts`; this ticket consumes them read-only.

- `packages/game/test` is owned by this ticket; T-0016 source behavior is covered
  by T-0010's browser suite.

### Test contract

- Formulas and constants: seed normalization is unsigned 32-bit; camera target,
  snap, update, and projection; HUD formatting from simulation state; input
  mapping for Q, W, Space, E, and R; DPR scaling; static test hooks.
- Expected values: seed wraps modulo 2^32; camera never rotates; HUD values
  match state; blur and page hide release latches; instructions mention Q, W,
  Space, E, R and staying inside the tunnel; renderer reads state without
  mutation.
- Thresholds: DPR 1 and 2; narrow and desktop layout; invalid and maximum
  seeds.
- Test file names: `packages/game/test/seed.test.ts`, `camera.test.ts`,
  `input.test.ts`, `hud.test.ts`, and `render.test.ts`.
- Table-driven cases: valid/invalid seeds, key mappings, HUD values, camera
  projections, and DPR/layout cases.

## Acceptance criteria

1. The pure game helpers, renderer, and static hooks are rebuilt from the spec.
2. Input mapping and latch reset behavior match the spec.
3. HUD and seed helpers are state-driven and pure where possible.
4. Instructions mention Q, W, Space, E, and R and describe staying inside the
   tunnel.
5. The layout is responsive and the canvas handles DPR.
6. The documented `data-testid` hooks are present and stable.
7. Rendering never mutates simulation or field state.
8. Typecheck, focused unit tests, and build pass.

## Edge cases

- Instruction text mentions every control and the tunnel.
- Invalid and maximum seed values.
- Blur or page hide with the rear latch on.
- Manual input while autopilot is active.
- Resize before the first render.
- Narrow viewport layout.
- Destroyed state and reset HUD values.

## Affected interfaces

Game pure modules, renderer modules, `packages/game/index.html`,
`packages/game/src/style.css`, and `packages/game/test`.
