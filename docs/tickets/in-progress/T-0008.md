## Original request

Split from the original T-0008 so the deterministic controller can be rebuilt
before the benchmark, which runs after T-0013 integration.

## Goal

Provide a deterministic, observation-driven controller that uses the full
sensor suite to follow the tunnel centerline safely and uses all three
thrusters.

## Current behavior

The old autopilot is tuned for the old gentle, constant-width tunnel.

## Desired behavior

- `createAutopilot()` returns a deterministic `Controller`.
- It uses the full observation: eye, direction, distance to start, velocity,
  tunnel center and heading, and nearest-wall clearance.
- It follows the centerline and tangent, uses the rear thruster for forward
  speed and bottom thrusters for lift and attitude, and cuts rear thrust when
  clearance is low.
- It prioritizes zero wall contact over speed.
- It is deterministic for the same observation sequence.
- It exclusively controls all three thrusters while active.
- The game calls it once per fixed tick when E is active; the simulation does
  not own the autopilot mode.

## Non-goals

- Benchmark thresholds and seed tuning (T-0014).
- Formal collision-free guarantees.
- Machine learning or training infrastructure.
- Changing controls, physics, tunnel, or sensors.

## Decision log

| Decision | Choice | Rationale |

| Controller | Deterministic, observation-driven | Spec |
| Safety | Zero contact over speed | Spec |
| Rear thrust | Cut when clearance is low | Safety governor |
| Benchmark | Separate T-0014 | Measurement after integration |

## Contract freeze

`Controller`, `Observation`, `Action`, and the autopilot benchmark contract
follow T-0003. The controller must not change the public API.

### Test contract

- Formulas and constants: `createAutopilot(): Controller`;
  `act(observation)` returns `Action { left, right, rear }`; the controller uses
  eye, direction, distance, velocity, tunnel center/heading, and nearest-wall
  clearance; identical observation replays produce identical actions.
- Expected values: all three thruster keys are present and boolean; the
  controller can command all three thrusters; rear thrust is cut when clearance
  is low; centerline and tangent following keep the ship away from walls in a
  short deterministic replay.
- Thresholds: the exact low-clearance threshold is implementation-defined; the
  tests assert the safety behavior, not a hard-coded threshold. The 8-seed
  benchmark thresholds belong to T-0014.
- Test file names: `packages/sim/test/autopilot.test.ts`.
- Table-driven cases: centered, near-wall, steep heading, zero speed, low
  clearance, and destroyed/autopilot-off observations.

## Acceptance criteria

1. `createAutopilot()` is deterministic and uses the full observation.
2. The controller exclusively controls all three thrusters when active.
3. It prioritizes zero contact and cuts rear thrust when clearance is low.
4. It follows the centerline and tangent.
5. Typecheck and focused tests pass.

## Edge cases

- Near-vertical climbs and dives.
- Minimum-width sections.
- Sharp width changes.
- Reset and repeated same-seed runs.
- Destroyed state and autopilot off.
- Manual input while active.
