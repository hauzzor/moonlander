## Original request

Add configurable gravity and separate bottom/rear thruster power from 0.1x to
10x, with live setters, observation exposure, and autopilot compensation.

## Goal

Extend the deterministic simulation with `gravityScale`,
`bottomThrusterScale`, and `rearThrusterScale`, preserving the fixed
`1/120` timestep and the default 8-seed autopilot benchmark.

## Current behavior

Gravity is the constant `1.62 m/s²`; bottom and rear thrusters use fixed 1800 N
and 900 N forces. The autopilot imports the gravity constant.

## Desired behavior

- Constants `GRAVITY_SCALE_MIN/MAX/DEFAULT` and
  `THRUSTER_SCALE_MIN/MAX/DEFAULT` (0.1, 10, 1).
- `SimulationOptions.gravityScale`, `bottomThrusterScale`,
  `rearThrusterScale`.
- `SimState`/`Observation` expose the three scales and effective `gravity`.
- `Simulation.setGravityScale`, `setBottomThrusterScale`,
  `setRearThrusterScale`; finite values clamp to 0.1-10, non-finite falls back
  to 1.
- Gravity applies in the fixed-tick force term; bottom/rear forces and torque
  scale independently at the mounts via
  `thrusterEffect(angle, action, bottomScale?, rearScale?)`.
- Autopilot uses observation `gravity`, `bottomThrusterScale`, and
  `rearThrusterScale`; the default benchmark remains scale 1.
- Reset preserves the configured scales.
- No simulation `timeScale`; time scaling stays in the game loop.

## Non-goals

- No game UI or time-scale work in this ticket (T-0021).
- No change to FIXED_DT, collision, sensor cadence, damage, or benchmark
  thresholds.
- No public API removals.

- `Simulation.setGravityScale(scale)`, `setBottomThrusterScale(scale)`,
  `setRearThrusterScale(scale)`.
- `thrusterEffect(angle, action, bottomScale = 1, rearScale = 1)`.
- Defaults and reset behavior as above.

### Test contract

- Gravity: first no-thrust tick
  `vy = (-GRAVITY * scale * FIXED_DT) / (1 + LINEAR_DRAG * FIXED_DT)`;
  terminal fall `GRAVITY * scale / LINEAR_DRAG`; 0.162, 1.62, 16.2 m/s².
- Power: bottom/rear force and torque scale independently; default output is
  bit-identical; combined lift follows scaled forces.
- Observation/state expose scales and effective gravity.
- Setter clamping and non-finite fallback; reset preserves scales.
- Same seed + scales + per-tick actions yields identical state; different
  scales change trajectory.
- Autopilot uses observed scales; default 8-seed benchmark still passes.
- Test files: `gravity.test.ts` (new), `thruster-scale.test.ts` (new), and
  updates to `simulation.test.ts`, `observation.test.ts`, `physics.test.ts`,
  `autopilot.test.ts`, `autopilot-benchmark.test.ts`, `helpers.ts`.

## Acceptance criteria

1. Gravity and bottom/rear scales clamp to 0.1-10 and default to 1.
2. Fixed 120 Hz stepping, collision, sensors, damage, and invulnerability are
   unchanged at default scales.
3. Effective gravity and scale values are exposed in state and observation.
4. The autopilot uses effective scales.
5. The default 8-seed benchmark passes unchanged.
6. Reset preserves scales; setters apply from the next tick.
7. Typecheck and focused tests pass.

## Edge cases

- Non-finite/zero/negative/out-of-range scales.
- Reset during flight and after destruction.
- Extreme gravity/power combinations.
- Autopilot at extremes (finite/deterministic smoke only).
- Pinned field and seed changes.
