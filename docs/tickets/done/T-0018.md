## Original request

Wave 6 review found that focusing or dragging the eye-sensor radius slider makes
`isEditableTarget` swallow Q/W/Space/E/R until focus leaves the range input. The
page must remain fully playable with the game keys.

## Goal

Keep the game keys working while the radius slider is focused, while still
letting text-entry controls (the seed input) capture typing.

## Current behavior

`packages/game/src/input.ts` treats every `input` element as editable, so a
focused `<input type="range">` blocks Q/W/Space/E/R. T-0010's radius-persistence
test blurs the slider before pressing R, masking the defect.

## Desired behavior

- Text-entry controls (`type="text"`, search, number, email, password, url, tel)
  and `textarea`/`contenteditable` keep capturing keys.
- A focused range slider does not block Q/W/Space/E/R.
- The existing seed-input focus behavior remains intact.
- Add a regression test at the unit and browser levels.

## Non-goals

- Changing slider interaction or layout.
- Changing key bindings.
- Editing game source outside `input.ts`.

## Decision log

| Decision | Choice | Rationale |
| --- | --- | --- |
| Editable detection | Text-entry controls only | Range sliders are controls, not text fields |
| Regression | Unit plus e2e | Prevent the blur-workaround from masking the defect |
