## Original request

Show a build number and build date/time in the game UI, and show the sensor
instruments only when autopilot is on. The user also wants a Change Log button
that opens a modal with an expandable history of all previous change logs.

## Goal

Make the running build identifiable, provide an in-game change log without a
runtime network dependency, and hide the entire sensor console and radar in
manual flight.

## Current behavior

- The top bar shows only the brand.
- The sensor console and radar are always visible.
- `game.ts` always updates the sensor console and always uses the radar renderer.
- Autopilot mode persists across `R`, but sensor UI visibility does not follow it.
- The Vite config injects no build metadata.

## Desired behavior

### Build info

- Top bar right: `BUILD 42 · abc1234 · 2026-10-21 02:30 UTC`.
- Build number = `GITHUB_RUN_NUMBER` or `DEV`; short SHA = `GITHUB_SHA` or git;
  build time = actual UTC build time.
- Inject metadata into `index.html` only; keep JS/CSS asset hashes stable.
- Hooks: `data-testid="build-info"` with `data-build-number`, `data-build-sha`,
  `data-build-time`, `data-build-source`.

### Change log

- `CHANGE LOG` top-bar button opens a modal `<dialog>`.
- Full scrollable curated history, newest first, each entry a `<details>` with
  short bullets; latest entry open by default.
- Source: `docs/CHANGELOG.md`, parsed at build time and injected as JSON into
  `index.html`; no runtime fetch or Markdown dependency.
- Close by Escape, outside click, or close button; focus returns to the button.
- While open, Q/W/Space/E/R do not affect the game.
- Hooks: `changelog-button`, `changelog-dialog`, `changelog-close`,
  `changelog-list`, `changelog-entry` with `data-expanded`.

### Sensor visibility

- Manual mode hides the entire `eye-sensor-panel` and the radar.
- Autopilot mode shows both.
- Radius slider is autopilot-only.
- `R` and seed loads preserve autopilot mode and visibility.
- Keep all sensor test IDs attached; hidden state uses `hidden`, `aria-hidden`,
  `inert`, `data-visible="false"`.
- Radar status hook: `data-testid="radar-status"` with `data-active`.
- Reveal forces chart resize/redraw.
- Focus is not left inside a hidden panel.
- Instructions expand into the freed layout space.

## Non-goals

- No simulation, physics, sensor math, autopilot, or public API changes.
- No runtime network dependency.
- No full Markdown renderer.
- No changelog editing from the UI.

- Changelog button/dialog/list/entry hooks.

## Acceptance criteria

1. Build label matches the confirmed format and attributes; CI shows the run
   number, local shows `DEV`; UTC build time.
2. Build metadata is HTML-only; two builds with different times keep identical
   JS/CSS filenames.
3. Change Log opens a full scrollable modal with all entries, newest first,
   expandable; Escape/outside/close work; focus returns.
4. Game keys do not affect the simulation while the modal is open.
5. Manual mode hides the entire sensor console and radar; autopilot shows them;
   `R`/seed loads preserve the mode and visibility.
6. Hidden panel keeps all documented hooks and reports `data-visible="false"`;
   radar status reports false.
7. Reveal redraws the chart at its real size.
8. No layout dead space or horizontal overflow in either mode.
9. Rendering remains read-only; scans/autopilot behavior unchanged.
10. `npm.cmd run verify`, local Playwright, and live suite pass with updated
    spec/hooks.

## Edge cases

- Local build without CI env or git.
- CI run number but missing SHA.
- UTC midnight.
- Empty/malformed changelog.
- Modal open plus game keys.
- E off while slider focused.
- R/seed load in both modes.
- Destruction while autopilot active.
- Hidden canvas with zero size then reveal.
- Narrow viewport with build label and open dialog.
