## Original request

"add more height changes to the tunnel. it should go vertically sometimes even"

This is the confirmed contract-freeze child of `docs/changes/2026-10-19-near-vertical-variable-width-tunnel.md`.

## Goal

Freeze the public tunnel and observation contract for near-vertical, variable-width terrain without changing generated geometry or gameplay behavior. The next ticket implements the behavior.

## Current behavior

- `Tunnel` has `halfWidth`, `centerAt(x)`, and `headingAt(x)`.
- `Observation.tunnelHalfWidth` is the constant 34 m and `tunnelCenterOffset` is a vertical offset.
- Tunnel constants still describe a 24 m bend, 0.35 slope, and 34 m half-width.
- The old generator's natural centerline variation remains within the new limits, so changing the limits does not change its generated walls.

## Desired behavior

- Add `halfWidthAt(x: number): number` to `Tunnel`.
- Keep `Tunnel.halfWidth` as the nominal 34 m.
- Add `TUNNEL_MIN_HALF_WIDTH = 25` and `TUNNEL_MAX_HALF_WIDTH = 55`.
- Change `TUNNEL_BEND_AMPLITUDE` to 150.
- Add `TUNNEL_MAX_CLIMB_ANGLE = (85 * Math.PI) / 180` and set `TUNNEL_MAX_SLOPE = Math.tan(TUNNEL_MAX_CLIMB_ANGLE)`.
- Keep `TUNNEL_HALF_WIDTH = 34`, `TUNNEL_CENTER_Y = 60`, and `TUNNEL_START_STRAIGHT = 120`.
- Document `TUNNEL_SAMPLE_STEP = 8` as the maximum wall chord length, not an x-step.
- Document that `Observation.tunnelHalfWidth` will become the local perpendicular half-width and `tunnelCenterOffset` will become the signed perpendicular offset. Do not implement those semantics in this ticket.
- Make the existing `createTunnel` return `halfWidthAt: () => TUNNEL_HALF_WIDTH`. This is a compiling no-behavior stub.
- Update `docs/spec.md` with the frozen contract and intended behavior.
- Update the frozen constant assertions and old bounds in `packages/sim/test/field.test.ts` and `packages/sim/test/simulation.test.ts` so the existing suite stays green. Do not add near-vertical behavior tests here.

## Non-goals

- Do not change the generator, wall geometry, sampling, chunking, collision, sensor, observation calculation, autopilot, renderer, or e2e behavior.
- Do not write the red behavior tests for near-vertical terrain; those belong to T-0002.
- Do not change progress, controls, damage, or outcome rules.
- Do not edit files outside the declared scopes.
