## Original request

Split from T-0011 so CI, GitHub Pages, and the live harness can be rebuilt once
the integrated game is playable, while docs reconciliation remains in T-0011.

## Goal

Ensure every green `main` build runs the full checks, deploys
`packages/game/dist` to GitHub Pages, and runs the live Playwright suite against
the deployed URL.

## Current behavior

The existing CI and delivery scripts target the old game. The integrated game is
produced by T-0009; the local browser suite is produced by T-0010.

## Desired behavior

- CI runs typecheck, unit tests, `sim:demo`, local Playwright, and production
  build on push and pull request.
- `main` deploys the built `packages/game/dist` through GitHub Actions Pages.
- The live Playwright suite runs against the deployed URL after deployment.
- `npm.cmd run deliver` verifies, commits intended changes, pushes `main`, waits
  for the live asset, and runs the live suite.
- No force-push, amend, reset, or clean.
- Delivery stops on verify, push, deployment, or live-suite failure.

## Non-goals

- Docs reconciliation (`README.md`, `docs/spec.md`, `docs/autonomy.md`), owned by
  T-0011.
- Changing game behavior, tests, or the public API.
- Adding deployment providers or secrets.
- Rewriting the ticket tooling.

## Decision log

| Decision | Choice | Rationale |
| --- | --- | --- |
| Pages | GitHub Actions artifact flow | Existing CI |
| Live suite | Full Playwright against Pages | Spec |
| Delivery | Direct push after verify and review | User selected |
| Timing | After T-0009 | CI must validate a playable build |

## Contract freeze

The documented commands, hooks, and benchmark in `docs/spec.md` are frozen by
T-0003 and the preceding tickets. The delivery and live scripts keep their
documented CLI behavior.

## Test matrix

| Area | Unit tests | E2E tests | Determinism/edge cases | Owner |
| --- | --- | --- | --- | --- |
| CI | — | Workflow runs typecheck, unit, `sim:demo`, Playwright, build | PR and main | release-engineer |
| Pages | — | Deploy job publishes `dist` | Main only | release-engineer |
| Live suite | — | Full live Playwright suite against Pages | Asset wait and timeout | release-engineer |
| Delivery | — | Stop on failure | No force-push | release-engineer |

## Acceptance criteria

1. CI runs the full verification and `sim:demo`.
2. `main` deploys to GitHub Pages.
3. The live Playwright suite passes against the deployed URL.
4. Delivery never force-pushes and stops on failure.
5. `npm.cmd run verify` and `npm.cmd run test:e2e:live` pass.
6. Typecheck and build pass.

## Edge cases

- Pages asset propagation delay.
- PR run without deployment.
- Live suite timeout.
- Missing or stale npm scripts.
- Delivery failure after a successful push.
- Concurrent delivery or live-suite runs.

## Affected interfaces

`.github`, `scripts`, `package.json`, and `package-lock.json`.

## Parallelization plan

- Independent units: CI workflow, Pages deployment, delivery/live scripts.
- Disjoint scopes: `.github`, `scripts`, and package files are owned only by this
  ticket; e2e tests are T-0010; docs are T-0011.
- Shared files / integration points: consumes the local e2e suite from T-0010 and
  the built game from T-0009 as read-only inputs.
- Wave and dependencies: wave 6 with T-0010; depends on T-0009.
- Max concurrency (default 2): 2.
- Coordination / handoff notes: run delivery and live verification serially; do
  not race T-0010's local Playwright server.
- Why sequential, if no split: CI, Pages, and delivery share package scripts and
  the deployment gate.

## Verification plan

1. Run `npm.cmd run verify`.
2. Run `npm.cmd run sim:demo`.
3. Deliver to `main`.
4. Wait for Pages and run `npm.cmd run test:e2e:live`.
5. Record the commit, deployment, and live result.
