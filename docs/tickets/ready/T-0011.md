## Original request

Split from the original T-0011 so CI, Pages, and the live harness (T-0017) can be
rebuilt in parallel with the Playwright suite (T-0010), then docs and the live
verification close out the rebuild.

## Goal

Reconcile the spec, autonomy guide, and README with the rebuilt game and confirm
the live deployment passes the full browser suite.

## Current behavior

The CI and live harness are rebuilt by T-0017 and the browser suite by T-0010.
The docs still contain T-0001 staging language and possibly the old 400/500/8
benchmark.

## Desired behavior

- `README.md`, `docs/spec.md`, and `docs/autonomy.md` describe the rebuilt game.
- The confirmed 200/300/4 autopilot benchmark is the only benchmark documented.
- Remove stale T-0001 staging language and old 400/500/8 references.
- Document the current commands, controls, hooks, and CI/Pages flow.
- Run `npm.cmd run verify`, `npm.cmd run sim:demo`, and
  `npm.cmd run test:e2e:live`.
- Record the live result and any residual risk.

## Non-goals

- Changing game behavior, tests, or public API.
- Rewriting CI, Pages, delivery, or ticket tooling (T-0017).
- Adding deployment providers or secrets.

## Acceptance criteria

1. Docs match the rebuilt game and the confirmed benchmark.
2. Stale staging and old benchmark references are removed.
3. The live Playwright suite passes against the deployed URL.
4. `npm.cmd run verify` and `npm.cmd run test:e2e:live` pass.
5. Residual risks are recorded.

## Edge cases

- Pages asset propagation delay.
- Live suite timeout or flake.
- Docs references to removed behavior.
- Missing or stale npm scripts.
- Benchmark values disagreeing across spec, autonomy, and tests.

## Affected interfaces

`README.md`, `docs/spec.md`, and `docs/autonomy.md`.

- Independent units: README, spec, autonomy guide, live verification.
- Disjoint scopes: docs only; CI/scripts are T-0017; e2e is T-0010.
- Shared files / integration points: consumes the final commands, hooks, and
  browser suite as read-only inputs.

- Coordination / handoff notes: run delivery and live verification serially;
  report the deployed URL, commit, and live result.
- Why sequential, if no split: docs and live verification are the final gate
  before T-0012.
